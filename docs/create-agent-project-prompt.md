# 一次性接入 Agent 项目的提示词

将下面的提示词交给支持读取仓库、执行命令和浏览器验证的编程助手，替换参数后执行。共享时保留密钥占位符，由接入者在自己的环境中填写。

```text
请在指定目录中创建一个独立 Next.js 对话示例项目，通过 shadcn Registry 安装本项目的 Agent UI，直接使用官方前端 SDK，对接指定 OpenAPI，并完成真实对话验证。

【项目参数】
项目父目录：<绝对路径>
项目名称：<例如 agent-chat-example>
Registry 地址或本地项目路径：<地址或绝对路径>
SDK 包名：@lingya-ai/agents-sdk
SDK 版本：<指定版本，或核对当前 Registry 要求的兼容版本>
SDK 本地安装包或源码路径：<可选；尚未发布 npm 时使用>
本地页面端口：<例如 4612>

【OpenAPI 参数】
OPENAPI_BASE_URL=<网关地址，保留实际租户域名>
OPENAPI_CHANNEL_ID=<渠道 ID>
OPENAPI_AK=<Access Key>
OPENAPI_SK=<Secret Key>
OPENAPI_EXTERNAL_USER_ID=<示例用户的稳定标识>

【执行要求】

1. 先检查当前 Registry、SDK 文档与源码，核对公开导出、客户端初始化方式、令牌认证、请求路径和流式传输契约。以当前实现为准，不凭记忆猜测接口。读取并遵守项目适用的 AGENTS.md。必需参数缺失时集中询问，不猜测凭据或渠道。

2. 在指定父目录创建独立 pnpm + Next.js App Router 项目，使用 React、TypeScript 和 Tailwind。原有前端、后端、SDK 和 Registry 项目只读，不修改其源码、依赖或配置。

3. 使用真实 shadcn CLI 初始化项目，并从 Registry 安装基础聊天组件和服务端令牌签发能力，不要手工复制组件来代替 Registry 安装。
   - Registry 尚未部署时，可临时提供本地 Registry 服务完成安装。
   - SDK 已发布时使用指定 npm 版本。
   - SDK 尚未发布时，使用可核验的本地安装包；将其放入新项目 vendor 目录，记录版本、来源和校验值，确保停止临时服务后仍可安装依赖。
   - 保留锁文件，提供可重复执行的 Registry 安装命令。
   - 如已有可用 Registry 产物，直接使用；缺少产物时，不修改只读源仓库，可在新项目缓存或临时副本中准备产物。

4. 直接将 SDK 作为标准 API 实现注入 UI Provider，复用 SDK 类型、认证和流式处理。
   - 不另写 HTTP 客户端、DTO 转换层、事件解析器或重复的协议适配层。
   - 默认使用 SSE。
   - 令牌申请与刷新遵循 SDK 的实际契约，不能假设令牌可重复使用；当前契约下每个请求或新流都需要独立签发一次性令牌，不缓存或共享同一令牌值。
   - 不自动重放可能已被后端接受的发送、审批等写请求。
   - 身份或渠道切换时更新 Provider 的隔离标识，释放旧请求、缓存与连接。

5. 将 AK/SK 仅保存在新项目服务端 .env.local 中，并确保该文件被 Git 忽略。
   - 提供不含真实密钥的 .env.example。
   - 使用 SDK 或 Registry 已提供的服务端签名与令牌签发能力。
   - 浏览器只获得短期令牌，禁止把 AK/SK 放入 NEXT_PUBLIC_*、客户端代码、页面属性、日志或文档。
   - 示例用户身份由服务端确定；正式接入时应替换为宿主应用认证产生的用户身份，不能信任浏览器提交的任意用户 ID。
   - 本地示例只监听回环地址；未接入宿主认证前，不将固定身份的令牌接口对外开放。

6. 如上游不支持浏览器跨域，创建受限的 Next.js 同源代理。
   - 只允许当前渠道的聊天 API 路径，不能成为任意 URL 代理。
   - 保留上游租户域名与 Host 语义。
   - SSE 响应直接透传，不缓冲、不重新解析业务事件。
   - 正确传递请求取消信号，处理断开与异常。
   - 如果 Node.js 无法解析 *.localhost，可在服务端连接层将其解析到回环地址，同时保留请求中的原域名；不要直接把上游地址改成 IP 导致租户路由失效。

7. 页面保持简单，复用 Registry 聊天组件，至少具备消息输入与发送、流式回复与停止生成、新建对话、会话 ID 写入 URL、刷新恢复历史、加载与错误反馈。保留组件已有交互，使用宿主 shadcn 语义令牌，不引入品牌字体或整套内部应用主题。遵守 Registry 的 Chromium 102 兼容要求，包括样式后处理配置。

8. 完成与变更范围相符的验证：
   - TypeScript、Lint、生产构建。
   - 依赖安装不依赖已停止的临时服务。
   - 浏览器实际打开页面并向真实渠道发送一条简短测试消息。
   - 确认助手实际返回内容，而非仅看到用户消息。
   - 确认刷新后历史消息恢复。
   - 检查浏览器控制台错误。
   - 检查浏览器构建产物不包含 AK/SK，仅输出检查结论，不输出密钥或令牌。
   如缺少凭据或后端不可用，明确报告阻塞原因，不得用模拟回复声称真实联调成功。

9. 编写 README，包含安装、环境变量、启动、Registry 重装方式、SDK 来源、请求链路和示例身份接入说明。不要写入真实密钥。

【交付方式】
直接实施并持续修复到验证完成，不只输出方案，不执行远程发布或部署。
执行中不得输出密钥或完整令牌。
完成后提供：
- 新项目路径与本地访问地址。
- 实际使用的 SDK 和 Registry 版本。
- 已通过的验证及尚未完成项。
- 真实对话截图。
- 启动和再次接入所需的最少命令。
```
