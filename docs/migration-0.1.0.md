# 0.1.0 初次移植说明

前端来源提交 `93dca9f4518634ccd9d6e6595c80291bc7d623bf`，后端来源提交 `3fc9a873e7e702b98d3e52a9b4a134bef96427a4`。来源仓库在移植时存在未提交改动，详细路径及每个移植文件的 SHA-256 见 `provenance/source.json`。

从当前 `packages/ai` 的完整聊天、会话列表及历史回放入口归集依赖，包含实际引用的 API、基础 UI、文件预览和图表实现。源码使用相对叶子导入，不依赖原仓库运行时。一次性来源采集脚本保留用于追溯，正常构建不运行它们，也不读取兄弟仓库。

## 接入变化

- `@workspace/*` 改为本项目内部叶子相对导入，分发后由宿主维护源码
- 移除 Studio RBAC、租户空间上下文、管理页面跳转和网络遥测；授权仍由后端执行
- Intlayer 字典一次性转换为带类型的中英文 Provider，默认中文，支持局部覆盖和插值
- 新增 OpenAPI 短期令牌客户端、全量契约操作入口、服务端签名与令牌 Handler
- 默认 SSE；WebSocket 使用后端定义的认证子协议，令牌不进入 URL
- 每个 Provider 身份拥有独立作用域客户端，切换时取消请求、卸载旧流并清理对应缓存；不会自动重放写操作
- 工作区和文件预览按原实现保留，基础 UI 适配宿主语义令牌，去除品牌字体和 Studio 全局主题
- 为 Chromium 102 增加 CSS 后处理、输入焦点与显式布局降级，模拟器避免使用较新的 Response.json 静态方法

## 独立修复

修复子 Agent 受控折叠切回非受控时残留展开状态；修复存储写失败后切回旧模式时被请求库短路的问题；SVG 加载标题使用纯字符串，避免 SSR 文案节点被转换为 `[object Object]`。

旧目标创建测试改为当前后端的发送消息目标模式契约；其他协议、终态、同步、审批、回答、目标、子任务、引用及工作区测试保留并在本项目执行。

## 升级边界

展示文件：`ai/agents`、`ai/components`、`ui`、`file-preview`、`charts`。

协议与状态：`openapi`、`api`、`ai/hooks/use-chat`、`ai/lib`、`i18n`。

安装新版本时，涉及的协议、状态、Schema 和展示文件必须一起更新并审查。条目使用重叠依赖闭包，重叠文件内容相同；保留本地改动时不要盲目覆盖。后续修复按需移植，不会与内部实现自动同步。

## 已知边界

基础 agent-chat 的闭包不包含 PDF、Office、ECharts 依赖；文件预览通过 agent-files 的 AgentFilePreviewsProvider 注入，SQL 图表通过 agent-sql 的 AgentSqlChartsProvider 注入。未安装时保留文件下载和 SQL 数据表入口。完整 agent-chat-workbench 自动组合上述能力，完整示例仍有大 chunk 提示；预览和图表实现采用动态加载。

真实测试渠道凭据尚未提供，真实渠道认证、跨域、WebSocket 代理、实际上传存储与导出未完成验收。本项目现采用 MIT 许可证，见根目录 LICENSE；包元数据保留 `private` 以防止意外发布到 npm。

## 认证契约的并行更新

2026-10-20 最终核对时，后端将短期令牌改为十分钟内有效且只能消费一次，业务失败也不会恢复已消费令牌。客户端因此改为每次 HTTP 请求、SSE 重连、WebSocket 握手单独调用 getToken，不缓存令牌，也不合并并发令牌值。这取代最初方案中的“合并并发令牌更新”，避免并发请求争用同一枚令牌而触发 401。接入方的服务端令牌接口必须逐次签发并禁止缓存。没有自动重放写操作。认证实现来源及哈希见 provenance/backend-auth.json。
